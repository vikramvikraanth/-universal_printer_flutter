messages across a boundary

A Flutter MethodChannel is a named, asynchronous message pipe. Dart and native code each hold a channel with the same name — that string is the entire binding. Everything else is serialize → cross → deserialize.

three invariants that keep it correct
01

Enums cross as strings

Each Dart enum carries its Kotlin .name as .wire — PrintAlign.center → "CENTER" — so two type systems stay in sync with no shared codegen.

02

Reply on the main thread

Blocking work runs on Dispatchers.IO; result.success() is always delivered back on Main — MethodChannel requires it.

03

State by handle, never by value

A live Printer (socket + FIFO queue) is kept in a native registry and referenced by id. The object never crosses the wire — only its handle does.

iOS · same channel

The iOS side registers the identical channel name and returns FlutterError("UNSUPPORTED_PLATFORM") — a deliberate no-crash stub, not a missing plugin. The Dart Platform.isAndroid guard short-circuits before the wire is even touched.
